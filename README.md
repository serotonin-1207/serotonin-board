# Serotonin 메모 보드

여러 사람이 함께 쓰는 **공유 메모 보드와 3팀 24시간 근무 달력**입니다. 서버 프로그램 없이 브라우저 화면(HTML·JS·CSS)만으로 동작하고, 저장소를 두 가지 중에서 고를 수 있는 시험판입니다.

| 버전 | 저장 위치 | 용도 |
|---|---|---|
| **Supabase** | 클라우드 (무료 요금제) | 어디서든 접속, 접속 코드로 보호 |
| **공유기 게스트** | 공유기에 연결한 USB SSD | 같은 내부망 안에서만 사용 |

현재 소스 버전은 0.3.0입니다. 실제 업무자료가 아닌 **시험용**입니다. 표시 이름은 본인 인증이 아닙니다(공유기 버전은 아래 서명 방식으로 보완).

## 제공 기능

- 인수인계·공지사항·업무 메모, 중요 고정, 처리 상태, 검색과 필터
- 수정할 때마다 새 기록을 쌓는 **수정 이력**, 동시 수정 보존과 정리, 휴지통과 복구
- 수정 기록 전체를 담은 JSON 백업 내려받기
- **근무 달력**: 2026-10-08을 1팀으로 시작해 1→2→3팀이 하루씩 반복(매일 09:00 교대), 휴가·교육·교대·훈련·기타 일정 등록
- 휴대폰·태블릿·PC 반응형 화면

## 빠른 시작

```bash
npm install
npm test          # 자동 시험 (수정 이력, 달력, 서명, 로컬 PostgreSQL 권한 시험)
npm run build     # dist/ 생성 (dist/supabase, dist/guest)
npm run preview   # 개발용 로컬 미리보기
```

`web/storage.js`는 `src/storage.mjs`에서 만드는 생성 파일이므로 직접 고치지 말고 `npm run build`로 갱신합니다. 빌드 버전과 캐시 갱신 값은 `package.json`의 `version`을 따릅니다. 코드 서식은 `.prettierrc.json`을 따릅니다.

## Supabase 버전 준비

1. 무료 Supabase 프로젝트를 만들고 Authentication에서 **Anonymous Sign-Ins**를 켭니다.
2. SQL Editor에서 `supabase/setup.sql` 전체를 실행합니다(여러 번 실행해도 안전합니다).
3. 접속 코드를 정해 해시로 등록합니다(`setup.sql` 끝의 `ADMIN STEP`). 코드를 등록하기 전에는 아무도 접속할 수 없습니다.
4. 프로젝트 주소와 **publishable 키**를 `supabase/public-config.json`에 적고 `npm run build`를 실행합니다.
   - 공개해도 되는 값만 넣으세요. `secret`·`service_role` 키와 데이터베이스 비밀번호는 어디에도 저장하지 않습니다.
5. 직원은 보드의 **연결 설정**에서 표시 이름과 접속 코드를 한 번 입력합니다.

자세한 순서와 한계는 [COMPARISON-SETUP.md](COMPARISON-SETUP.md), [TEST-PLAN.md](TEST-PLAN.md)를 참고하세요.

## 텔레그램 일정 알림 (0.10.0, Supabase 버전)

달력의 **일정**(휴가·교육·훈련 등)을 부서별 텔레그램 대화방으로 알려 줍니다. **인수인계는 알리지 않고** 보드에서만 확인합니다. 일정 제목은 그대로 보냅니다.

- **아침 요약**(기본 09:00): 오늘 근무팀(순환 부서만)과 오늘 일정. **저녁 예고**(기본 18:00): 내일 근무팀과 일정(내일 일정이 없으면 보내지 않음). **변경 알림**: 새 일정·변경·삭제를 마지막 저장 뒤 3분이 지나면 한 메시지로 묶어서 보냅니다. 켜기 전의 일정은 알리지 않습니다.
- 설정은 **관리 → 텔레그램 일정 알림**에서 부서별로 합니다(대화방 연결, 켜기, 종류, 시각, 시험 메시지, 연결 해제). 한 대화방은 한 부서에만 연결됩니다.
- 봇 토큰은 서버 함수의 비밀 값 `TELEGRAM_BOT_TOKEN`에만 둡니다. 저장소·화면·DB에는 저장하지 않습니다. 준비 순서는 [텔레그램 연결 준비 안내](docs/telegram-setup.md), 설계는 [설계 검토](docs/telegram-design.md)를 보세요.
- 서버: `supabase/functions/telegram-notify`(Edge Function, JWT 확인 끔)를 `pg_cron`이 5분마다 호출합니다(`supabase/migrations/0.10.0-cron.sql`). 관리자 화면에서 부르는 동작은 관리자 로그인을 서버에서 확인합니다.
- 기존 DB는 `supabase/migrations/0.10.0-telegram.sql`을 한 번 실행하세요(`setup.sql`에도 포함).

## 자주 쓰는 목록·담당자·주간 보기 (0.9.0)

- **자주 쓰는 목록**: 인수인계 화면의 **자주 쓰는 목록**에서 매일 반복하는 점검 항목을 한 줄에 하나씩 저장해 두고 **오늘 목록에 불러오기**를 누르면 한 번에 들어갑니다(최대 25개). 오늘 목록에 이미 있는 항목과 목록 안에서 반복되는 줄은 건너뜁니다. 목록도 수정 이력을 가지므로 지워도 휴지통에서 복구할 수 있고, 같은 부서만 봅니다.
- **담당자**: 항목마다 담당자(선택)를 둘 수 있습니다. 빠른 입력창에 `@홍길동 펌프 점검`처럼 쓰거나, 줄의 사람 버튼으로 **내가 맡기/담당 해제**, 편집창의 담당자 칸으로 지정합니다. **내 담당만** 체크하면 내 항목만 보입니다. 복사한 목록과 CSV에도 담당자가 들어갑니다.
- **달력 주간 보기**: 달력 상단의 **월간/주간**으로 바꿉니다. 주간은 일정을 줄이지 않고 모두 보여 주며, 좁은 화면에서는 날짜 순 목록이 됩니다. 선택은 기억됩니다.
- 기존 DB는 `supabase/migrations/0.9.0-templates.sql`을 한 번 실행하세요(`setup.sql`에도 포함).

## 운영 기능 (0.8.0, Supabase 버전)

- **백업 복원**: **기록 내려받기 → 백업 파일로 복원**에서 JSON 백업을 불러오면 이 부서에 없는 기록만 원래 시각 그대로 다시 채웁니다(이미 있는 기록은 건드리지 않고, 두 번 해도 같습니다). 복원된 기록은 수정 기록에 "백업에서 복원됨"으로 표시됩니다. 다른 부서의 백업이면 경고합니다.
- **부서 관리(관리자)**: 하단의 **관리**에서 관리자 코드를 입력하면 부서 만들기(접속 코드 자동 발급, 한 번만 표시), 이름·순환 근무·파일 용량 변경, 접속 코드 다시 발급, 가입자 목록과 제거를 할 수 있습니다. 관리자도 다른 부서의 메모와 파일은 볼 수 없습니다. 관리자 코드는 `serotonin_settings`에 해시로만 저장하며, 바꾸려면 SQL로 `admin_code_hash`를 새 해시로 바꿉니다.
- **서버 자동 삭제**: `supabase/functions/purge-files`(Edge Function)를 `pg_cron`이 10분마다 호출해 만료된 파일을 저장소에서 지웁니다(`supabase/migrations/0.8.0-cron.sql`). 함수는 입력을 받지 않고 이미 만료된 파일만 지우므로 별도의 비밀 값이 없습니다(JWT 확인은 끔). 프로젝트가 일시 정지되면 예약 작업도 멈추며, 접속한 브라우저의 정리가 보조로 동작합니다.
- **잠들기 방지**: `.github/workflows/keepalive.yml`이 이틀마다 공개 함수 `serotonin_ping`을 호출합니다. GitHub는 60일 동안 커밋이 없으면 예약 작업을 멈추므로, 가끔 커밋이 있어야 합니다.
- **봇 방지(선택)**: 임시 계정을 대량으로 만드는 것을 막으려면 Cloudflare Turnstile 위젯을 만들고, 사이트 키를 `supabase/public-config.json`의 `turnstileSiteKey`에 넣고 빌드한 뒤, Supabase Authentication → Attack Protection에서 CAPTCHA를 켜고 **비밀 키는 Supabase 화면에 직접 입력**하세요. 사이트 키는 공개해도 되지만 비밀 키는 저장소에 넣지 마세요.

## 파일 주고받기 (0.7.0, Supabase 버전)

사이드바의 **파일**에서 같은 부서원끼리 파일을 주고받는 **임시 파일함**을 씁니다.

- 파일 하나당 **최대 50MB**(무료 요금제의 고정 한도), 종류 제한 없음. 휴대폰에서도 바로 올릴 수 있고, 터치 기기에는 **사진 찍기** 버튼이 나옵니다.
- **보관 기간은 최대 7일**(기본 7일): 7일·3일·1일·6시간·1시간 또는 삭제 시각을 직접 지정합니다. 7일 상한은 DB가 강제합니다.
- **즉시 삭제**는 같은 부서원 누구나 할 수 있습니다(버튼을 두 번 눌러야 지워지며 되돌릴 수 없음).
- **자동 삭제**: 만료된 파일은 목록에서 바로 사라지고, 그 부서의 누군가의 브라우저가 열려 있는 동안 10분 안에 저장소에서도 실제로 지워집니다. 아무도 접속하지 않으면 실제 삭제는 다음 접속 때 이뤄집니다. 서버에서 확실하게 지우려면 `pg_cron`과 서버 함수(Edge Function)를 추가해야 합니다.
- 비공개 저장소이며 다른 부서는 목록·내려받기·업로드·삭제를 할 수 없습니다. 내려받기 주소는 1분만 유효하고 항상 "다운로드"로 내려갑니다(사이트 안에서 열리지 않음).
- 부서 용량은 기본 **400MB**입니다(`serotonin_depts.file_quota_bytes`). 무료 요금제의 전체 저장 공간(1GB)을 부서들이 나눠 쓰므로 부서가 늘면 조정하세요.
- 누가 언제 무엇을 올리고 지웠는지는 `serotonin_file_log`에 파일 이름과 크기만 남습니다(내용은 없음). SQL Editor에서 조회합니다.
- 바이러스 검사는 없습니다. 출처를 모르는 파일은 받은 뒤에도 열지 마세요.

## 기록 내려받기와 이 기기 저장 (0.6.0)

- 하단의 **기록 내려받기**(또는 연결 설정)에서 지금까지의 **모든 기록**을 파일로 받습니다.
  - **인수인계 일지 (CSV)**: 근무일마다 그날의 목록을 그대로 담습니다(완료 여부, 이월 일수). 엑셀용.
  - **항목 목록 (CSV)**: 모든 항목의 현재 상태, 쓴 사람, 완료한 사람과 시각. 엑셀용.
  - **수정 이력 전체 (CSV)**: 저장된 모든 기록을 시간순으로. 감사용.
  - **전체 백업 (JSON)**: 모든 기록을 원형 그대로. 보관용.
  - CSV는 UTF-8(BOM)이라 엑셀에서 한글이 깨지지 않으며, `=`·`+`·`-`·`@`로 시작하는 칸은 엑셀이 수식으로 실행하지 않도록 처리합니다.
- 받은 기록은 **이 브라우저(IndexedDB)에도 저장**해 두고, 다음에 열 때는 새로 생긴 변경분만 서버에서 받습니다(수정 기록은 바뀌지 않으므로 안전합니다). 같은 계정만 이 저장분을 다시 쓰고, 7일마다 또는 연결 설정의 **서버에서 전부 다시 받기**를 누르면 전체를 다시 받습니다. 공용 PC에서는 연결 설정의 **이 기기에 저장된 기록 지우기**를 누르세요.

## 부서(공간) 분리 (0.5.0, Supabase 버전)

한 링크와 한 프로젝트에서 여러 부서가 서로 내용을 볼 수 없게 나눠 씁니다.

- 부서마다 **접속 코드를 따로** 발급합니다. 코드를 입력한 브라우저(임시 계정)는 **그 부서에만** 속하며, 읽기·쓰기는 DB 권한(RLS)이 부서별로 막습니다. 다른 부서의 코드를 입력해도 이미 속한 부서는 바뀌지 않습니다.
- 부서는 `rotating`(순환 근무 여부)을 가집니다. 순환 부서는 09:00에 하루가 바뀌고 달력에 팀(1→2→3)이 표시되며, **내근 부서**는 자정에 하루가 바뀌고 팀 표시가 없습니다.
- 새 부서 만들기: `npm run new-dept -- rescue "구조대"` (내근이면 `--office`를 덧붙임). 출력된 SQL을 SQL Editor에서 실행하면 됩니다. 접속 코드는 `.work/dept-codes.txt`에만 저장되고 화면에는 나오지 않습니다.
- 이름 변경·내근 전환·가입자 조회·한 사람이 두 부서에 가입했는지 점검하는 SQL은 `supabase/setup.sql` 끝의 ADMIN 주석에 있습니다.
- 한계: 임시 계정 방식이라 브라우저 데이터를 지우고 다른 부서 코드를 넣으면 다른 부서에 가입할 수 있습니다. 코드는 해당 부서원에게만 알리고, 가입 때 입력한 이름으로 중복 가입을 점검하세요.
- 기존 0.3/0.4 프로젝트는 `supabase/migrations/0.5.0-departments.sql`을 실행한 뒤 `setup.sql`을 실행하세요(기존 기록과 코드는 첫 부서 `dept1`로 옮겨집니다).

## 인수인계 체크리스트

사이드바의 **인수인계**에서 근무일(09:00~다음 날 09:00) 단위의 체크리스트를 관리합니다.

- 항목을 쓰고 Enter로 추가합니다. 여러 줄을 붙여 넣으면 줄마다 항목이 되고(앞의 `-`, `1)`, `☐` 등은 지웁니다), **자세히**로 메모를 달 수 있습니다.
- 체크하면 완료로 옮겨 가고, 다시 누르면 해제됩니다. 별표로 중요 표시를 합니다.
- 끝나지 않은 항목은 다음 근무일에 **자동으로 넘어오고**(`이월 N일째` 표시), 완료한 항목은 완료한 다음 날부터 목록에서 빠집니다.
- 지난 근무일은 날짜 이동 버튼, 날짜 선택, 하단의 **최근 14일** 칩으로 봅니다. 그날 체크했던 상태를 수정 기록에서 되살려 그대로 보여 주며(읽기 전용), 아무것도 지워지지 않습니다.
- **목록 복사**로 그날의 목록을 메신저에 붙여 넣기 좋은 글로 복사합니다.
- 인수인계 항목은 메모 보드에는 나타나지 않습니다(삭제하면 휴지통에서 복구).

## 근무 달력

사이드바의 **근무 달력**에서 월 달력을 봅니다. 달력 위의 이전 달·다음 달·오늘·날짜 선택 버튼으로 이동합니다(2000~2099년). 날짜를 누르면 그날의 근무 팀과 일정이 나오고 **일정 추가**로 등록합니다. 일정도 메모와 같은 수정 기록 저장소를 쓰므로 수정 이력과 복구가 그대로 적용됩니다. 순환 기준일과 팀 수는 `web/core.js`의 `TEAM_ANCHOR_DAY`, `TEAM_COUNT`에 있습니다.

## 저장과 충돌

한 파일(행)을 여러 사람이 덮어쓰지 않습니다. (체크 한 번도 기록 한 건이므로 Supabase 버전은 기록 한도를 20,000건으로 두고, 읽을 때는 마지막 이후 변경분만 받습니다.) 저장마다 새 기록을 만들고 기존 기록은 유지합니다. 각 기록은 부모 기록 ID와 메모 전체를 포함합니다. 동시에 같은 부모에서 수정하면 두 내용을 모두 보관하고 충돌로 표시하며, 사용자가 최신 기록을 부모로 삼아 정리하면 해소됩니다. 저장 뒤에는 반드시 다시 읽어 내용이 같을 때만 "저장됨"으로 표시합니다.

## 공유기 게스트 버전과 작성자 서명

저장은 공유기 파일 탐색기의 업로드 기능과 URL 서비스를 이용하며, 공유기의 게스트 로그인이 필요합니다. 제조사 펌웨어의 내부 기능에 의존하므로 펌웨어가 바뀌면 다시 확인해야 합니다. 이 버전은 저장마다 브라우저에서 만든 Ed25519 서명을 붙이고, 관리자가 올린 `users.json`의 공개 열쇠와 대조해 작성자를 표시합니다(인증·미등록·미인증·서명 오류). 계정별 폴더 권한 시험은 `web/folder-probe.html`을 사용합니다. 자세한 내용은 [TEST-PLAN.md](TEST-PLAN.md)를 참고하세요.

## 현재 한계

- 시험판이며 수정 기록은 1,000개로 제한합니다. 자동 백업과 백업 복원은 아직 없습니다(내려받은 JSON을 별도로 보관하세요).
- 클라우드 임시 계정은 브라우저 데이터를 지우면 이어지지 않습니다. 이름 확인은 본인 인증이 아닙니다.
- 접속 코드를 아는 사람은 누구나 읽고 쓸 수 있습니다. 민감한 업무자료는 기관이 승인한 환경에서만 사용하세요.
- 무료 요금제의 용량·일시 중지 정책을 확인하고 운영하세요.
